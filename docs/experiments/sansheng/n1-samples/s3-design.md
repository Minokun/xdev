# demo-app 定时任务调度系统 · 设计文档

版本：v0.1　状态：待评审　项目代号：demo-app

## 1. 背景与功能描述

demo-app 目前依赖散落在多台机器上的系统 crontab 与人工触发脚本来执行周期性的清理、对账与数据同步工作，存在配置不可见、执行结果无记录、失败无感知等问题。本设计引入一个进程内定时任务调度子系统，以 HTTP JSON API 的形式对外提供四类核心能力：

1. **任务注册**：提交名称、cron 表达式与执行命令，持久化到 PostgreSQL；
2. **调度执行**：服务进程内的调度循环按 cron 表达式周期触发任务，以子进程方式执行并捕获结果；
3. **执行日志查询**：每次执行落一条日志，支持按任务分页查询；
4. **任务列表查看**：列出全部任务及其状态与下一次触发时间。

系统面向内部运维与后端开发者，使用方通过 curl 或脚本调用 API 完成任务的全生命周期管理。调度器与 API 同进程部署，任务命令以本地子进程方式执行。

## 2. 核心需求（功能点）

### F1 任务注册
- `POST /jobs` 接收 JSON：`name`（全局唯一，1–64 字符）、`cron`（5 段标准 cron 表达式）、`command`（本地可执行命令，含参数）、`description`（可选）。
- 注册成功后写入 `jobs` 表并返回 `201` 与任务 ID；`name` 重复返回 `409`；`cron` 非法返回 `400` 及具体错误信息；新任务默认状态为 `active`。

### F2 cron 表达式解析与校验
- 支持标准 5 段 cron：分、时、日、月、周；支持 `*`、`,`、`-`、`/` 四种语法元素。
- 注册时即时校验；调度时由解析器计算"给定时间之后的下一次触发时刻"（nextRun）。
- 不支持秒级字段，不支持 `@daily` 等宏，不支持 `L`/`W`/`#` 扩展语法；非法输入必须明确报错而非静默兜底。

### F3 调度执行
- 进程内调度循环每秒扫描一次到期任务（`next_run_at <= now()` 且状态为 `active`），到期即触发。
- 触发方式：以子进程执行 `command`，捕获退出码与 stdout/stderr；单次执行最长 10 分钟，超时杀死子进程并记为 `timeout`。
- 防重入：同一任务上一次执行未结束时跳过本次触发，并记录一条 `skipped` 日志。
- 执行完成后更新任务的 `last_run_at` 与 `next_run_at`。

### F4 执行日志查询
- `GET /jobs/:id/logs?page=&size=` 返回该任务的历史执行记录，按开始时间倒序分页，响应含 `total`。
- 单条日志字段：`started_at`、`finished_at`、`status`（success/failed/skipped/timeout）、`exit_code`、`stdout_tail`（截取输出末尾 4KB）、`error_message`。

### F5 任务列表查看
- `GET /jobs` 返回全部任务：`id`、`name`、`cron`、`command`、`status`、`last_run_at`、`next_run_at`、`created_at`。
- 支持按 `status` 过滤与按 `name` 模糊搜索；默认按 `created_at` 倒序；`next_run_at` 由 cron 表达式实时计算，语义须与调度器一致。

### F6 单个任务暂停/恢复
- **支持暂停/恢复单个定时任务，暂停期间不触发、恢复后按原 cron 继续。**
- 暂停：任务状态置为 `paused`，调度循环跳过该任务；其 cron 配置、历史日志与注册信息全部保留。
- 恢复：状态置回 `active`，以恢复时刻为基准按原 cron 表达式重新计算 `next_run_at`；暂停期间错过的触发**不做补跑**。
- 对不存在的任务或对已处于目标状态的任务重复操作，返回 `409` 并说明当前状态。

## 3. 非目标

- **不做分布式调度**：单进程单实例部署，不处理多副本选主、脑裂与任务分片。
- **不做任务编排**：任务之间无依赖、无 DAG、无回调链、无失败重试策略（超时即终止）。
- **不提供 Web UI**：仅暴露 HTTP JSON API，交互由调用方自行实现。
- **不做资源隔离**：任务命令直接以子进程运行在宿主机，不引入容器或沙箱。
- **不处理跨主机环境分发**：命令所依赖的二进制与环境变量由部署方保证。

## 4. 约束

- 技术栈：Node.js ≥ 20、TypeScript ≥ 5、Express 4、PostgreSQL ≥ 14；脚本一律用 `node` 直接运行。
- 调度精度：调度 tick 为 1 秒，cron 最小字段为分钟；允许最多 1 个 tick 的触发延迟。
- 时区：存储与计算统一使用 UTC；API 入参出参均为 ISO 8601 UTC 时间字符串。
- 资源限制：单任务单次执行最长 10 分钟；stdout/stderr 仅保留尾部 4KB 入库，完整输出不落库。
- 数据库变更一律通过带序号的 SQL 迁移文件执行，不允许手工改表。
- 验证方式以真实命令为准：单元/集成测试用 `npm test`，接口行为用 `curl` 实测，禁止仅以人工目测代替验证。

## 5. 验收标准

| 功能点 | 验收标准 |
|---|---|
| F1 | `curl -X POST /jobs` 合法入参返回 201 且数据库可查；重名返回 409；非法 cron 返回 400 |
| F2 | 解析器单测覆盖 `*/5 * * * *`、`0 9-18 * * 1-5`、`15,45 * * * *` 等用例；非法输入抛出明确错误 |
| F3 | 注册 `* * * * *` 任务后 90 秒内，日志表可观察到至少 1 条 `success` 记录；并发触发不产生重入 |
| F4 | 任务执行 ≥3 次后，`GET /jobs/:id/logs` 分页返回，字段齐全、倒序正确、`total` 准确 |
| F5 | `GET /jobs` 返回全部注册任务，`next_run_at` 与 cron 语义一致；过滤与模糊搜索生效 |
| F6 | 暂停后连续 2 个 cron 周期无新执行日志；恢复后下一个 cron 周期内恢复触发，且暂停期间不补跑 |

## 6. 风险与开放问题

- 子进程执行宿主命令存在安全隐患，上线前需做网络隔离与鉴权（本期先用内网 + 简单 token）。
- 单进程调度在服务重启期间会错过触发；本期接受该窗口，重启后以当前时刻重算 `next_run_at`，不补跑。
- 日志表随时间增长，后续版本需增加归档清理策略（可复用本系统注册一个清理任务）。
