# demo-app 优惠券引擎设计文档

## 1. 功能描述

优惠券引擎为 demo-app 电商平台提供完整的优惠券生命周期管理能力，覆盖券模板的创建与管理、券的发放（用户领取与运营定向发放）、用户券列表查询、下单核销、过期处理、叠加规则控制以及结算金额计算。引擎作为独立业务模块运行于 Python FastAPI + SQLAlchemy + PostgreSQL 技术栈之上，通过 REST API 同时对内（订单服务、运营后台）和对外（C 端用户）提供能力，并为每笔券的状态变更留存审计流水，支撑后续对账与运营分析。

引擎涉及两类核心角色：运营人员负责券模板的全生命周期管理与定向发放；C 端用户负责领取、查看并在下单时使用券。订单服务是引擎最重要的上游协作方：下单结算时向引擎发起券可用性查询与核销请求，引擎返回抵扣结果供订单服务组装应付金额。引擎自身不处理支付、不感知商品库存，仅对"券"这一营销资产的状态与计算规则负责，边界清晰、职责单一。

## 2. 核心需求

- **F1 券模板管理**：运营人员可创建、编辑、上架、下架券模板。模板字段包括：券名称、券类型（满减券 / 折扣券 / 无门槛券）、面额或折扣率、使用门槛（最低订单金额）、适用范围（全场 / 类目 / 指定商品）、有效期类型（固定日期区间 / 领取后 N 天有效）、发行总量、每人限领数量、状态（草稿 / 上架 / 下架）。已上架模板的关键字段（类型、面额）禁止修改。

- **F2 券发放**：支持两种发放方式：(a) 用户在前台主动领取，受模板库存与每人限领数量约束；(b) 运营后台向指定用户集合定向批量发放。发放接口必须幂等（携带 Idempotency-Key 的重复请求不重复发券），库存扣减必须防超发（原子条件更新，不允许"先查后改"）。

- **F3 用户券列表**：用户可查询名下全部券，按状态筛选（未使用 / 已使用 / 已过期），支持按面额、有效期排序与分页。列表需实时反映券状态：已过有效期的券不得再以"未使用"状态展示，查询时应对临界过期券做惰性过期处理。

- **F4 券核销**：用户在下单时使用券，系统校验券归属、状态（未使用）与有效期后，将券置为已使用，并记录核销订单号与核销时间；同一订单号的重复核销请求返回首次结果，不重复扣减。

- **F5 过期处理**：系统通过分钟级定时任务扫描并批量更新过期券状态为"已过期"，同时写入状态流转流水；过期判断需兼容固定有效期与动态有效期两种模板类型。

- **F6 叠加规则：同一订单同类型券不可叠加，每单最多使用一张。** 一笔订单无论用户持有多少张可用券，结算时只能选择一张参与抵扣；不允许一笔订单同时使用两张或以上券，也不允许同类型券（如两张满减券）叠加抵扣；选择新券需先取消原已选券。

- **F7 结算计算**：结算服务根据订单商品总额与用户选中的券计算实付金额：满减券满足门槛后按面额扣减，不满足门槛时返回原因；折扣券按折扣率折算，保留两位小数（ROUND_HALF_UP）；无门槛券直接扣减。券抵扣金额不得超过订单商品总额，实付金额下限为 0.01 元。全程使用 Decimal 计算，禁止浮点运算。

- **F8 审计与追溯**：券的发放、核销、过期等全部状态变更写入流水表，支持按券 ID、用户 ID、订单号三个维度追溯完整生命周期。

## 3. 非目标

- 不包含红包、积分、礼品卡等其他营销资产能力；
- 不支持券的转赠、拆分、合并与二级市场流通；
- 不做秒杀式瞬时高并发抢券的专项优化，仅保证常规并发下不超发、不重发；
- 不对接第三方支付渠道的代金券体系；
- 不支持跨店铺、跨平台通用券的清结算。

## 4. 约束

- 技术栈：Python 3.11+、FastAPI、SQLAlchemy 2.x（async）、PostgreSQL 14+；迁移使用 Alembic；测试使用 pytest + httpx；定时任务使用 APScheduler。
- 金额字段统一使用 Numeric(12,2)，应用层使用 decimal.Decimal 参与计算。
- 券状态流转为单向状态机：unused → used / expired，禁止逆向流转。
- 写接口必须幂等；库存扣减依赖数据库原子 UPDATE 或行锁，禁止非原子的"查-改"两步操作。
- API 遵循 REST 风格，统一响应结构与业务错误码；时间统一使用 UTC 存储、东八区展示。
- 过期扫描任务需分批执行，避免长事务锁表，并提供手动触发入口便于测试与运维。

## 5. 验收标准

- A1：运营创建模板并上架后，用户可正常领取；累计发放不超过发行总量，同一用户不超过限领数量；重复领取请求幂等。
- A2：用户券列表状态准确、筛选 / 排序 / 分页正确，过期券不以可用状态展示。
- A3：券核销后状态为已使用，记录订单号与核销时间，该券不可再次用于任何订单；同订单重复请求返回首次结果。
- A4：同一订单尝试使用多张券或同类型券叠加时被拒绝，每单最多一张券生效。
- A5：结算计算与券类型规则一致，精度到分，实付金额不低于 0.01 元，边界金额（门槛恰等、面额大于订单额）行为正确。
- A6：定时任务执行后，所有超过有效期的券被标记为已过期并留有流水，未过期券不受影响。
- A7：全部 API 具备对应 pytest 用例并通过，核心流程可用 curl 命令手工复现。
