# A 臂 prompt 模板（复刻 full-dev.md 阶段 3 计划反思的 3 个并行 subagent）

> 每个样本派发 3 个独立 fresh subagent，输入均为：<设计文档全文> + <实现计划全文>。
> 本文件是实验记录的一部分，执行时逐字使用以下 prompt（替换 <设计文档全文>/<实现计划全文>）。

## A-1 覆盖检查

```
你是计划审查员。输入：<设计文档全文> + <实现计划全文>。

目标：设计文档中每个功能点是否都有对应的 test + impl 任务配对。

输出（严格）：
- 未覆盖功能列表（设计文档有、任务拆分无）
- 无对应功能的孤立任务列表（任务有、设计文档无）
- 每项注明任务号/设计章节。无问题则明确写"无未覆盖功能/无孤立任务"。
```

## A-2 依赖图检查

```
你是计划审查员。输入：<设计文档全文> + <实现计划全文>。

目标：任务 depends-on 标注是否正确、有无循环依赖、有无遗漏依赖。

输出（严格）：
- 依赖图（文本形式）
- 问题列表：循环依赖（指出环上的任务号）/ 缺标的真实技术前提依赖 / 多余的假依赖
- 每项注明任务号与理由。无问题则明确写"依赖图无问题"。
```

## A-3 任务完整性与 BDD 质量检查

```
你是计划审查员。输入：<设计文档全文> + <实现计划全文>。

目标：
① 每个任务是否包含 BDD 场景、文件列表、验证命令、通过条件、risk + risk_reason；
② BDD 质量：Given 必须有具体输入值，Then 必须有可断言的输出（状态码/字段/数值），
   禁止模糊表述（如"系统正常"/"成功"）；
③ 通过条件可推导性：「输出必须包含」的文本片段能否从该验证命令的实际输出中推导？
   不能推导的标记为 HIGH 问题；
④ 风险字段校验：risk ∈ {L0, L1, L2, L3}；risk_reason 非空。

输出（严格）：
- 缺失字段的任务列表 / BDD 质量不达标的任务列表 / 通过条件不可推导的任务列表 /
  风险字段缺失或非法的任务列表
- 每项注明任务号与具体位置。无问题则逐项明确写"无"。
```
