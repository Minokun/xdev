# Judge 盲评 prompt 模板

> 每份样本的每个臂跑完后，由一个独立 judge subagent 对照预登记缺陷清单判定命中。
> judge 不知方案背景、不知臂的身份（输出以匿名标签 arm-X 呈现）。

```
你是公正的评审员，不参与实验设计。输入三份材料：

【材料 1：预登记缺陷清单】
<n1-defect-registry.md 中该样本的段落>

【材料 2：审核输出 arm-X】
<该臂全部 subagent 的原始输出>

任务：对照材料 1，判定材料 2 命中了哪些缺陷。

命中标准（严格执行，不放宽）：
- 命中 = 输出明确指出了缺陷所在的任务号/位置，且描述的问题本质与登记缺陷一致。
  措辞不必相同，但必须能定位到同一处。
- 模糊提及不算命中（如"有些依赖可能有问题"而未指明任务号）。
- 命中清单之外的额外发现记入 "extra_findings"，不参与命中统计。

输出（严格 JSON）：
{ "hits": ["S1-D1", "S1-D3"],
  "misses": ["S1-D2"],
  "extra_findings": ["<一句一条>"],
  "false_alarms": ["<输出中指控的、但不在登记清单且经判断并非真实缺陷的条目，一句一条>"] }
```

## N2 误封率专用 judge 变体

```
你是公正的评审员。输入：一份历史已批准实现计划的 Gate 审核输出（verdict/reasons/missing）
+ 计划全文（如需核对）。

任务：
1. verdict 是 approve 还是 reject；
2. 若 reject：逐条复核 reasons——对照计划全文判断每条是否指向真实存在的缺陷
   （真实缺陷=客观可验证的错误/缺失，非风格偏好）；
3. 输出：{"verdict": "...", "true_defects": [...], "false_alarms": [...]}
false_alarms 非空 = 误封证据；true_defects 非空 = 不算误封（反而是增量证据）。
```
