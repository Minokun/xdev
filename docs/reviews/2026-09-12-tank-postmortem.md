# 坦克大战三轮 bug 复盘：为什么闸门全绿、用户三分钟踩雷（2026-09-12）

> 对象：session-6a7be427（坦克大战复刻），xdev 流程第二次实盘。
> 用户侧事实：首轮交付后上手即报"子弹图标不对 + 间歇无法移动"（T3）；修复轮交付后又报
> "所有坦克全部都无法左右移动"（T6）。本文回答：**这些 bug 为什么能穿过全部闸门**。
> 证据均为 transcript / 仓库实查，未采信任何会话自述。

## 1. 三个 bug 的根因与逃逸路径

| 轮 | 用户报告 | 根因（transcript 取证） | 逃逸原因 |
|---|---|---|---|
| T3 | 子弹图标不对 | ROM 8×16 精灵模式下 tile 字节 bit0 选图案表；子弹/道具/护盾/火花在 **PT1 背景表**，渲染器把正索引一律送 PT0 精灵表；子弹还被按 2×2 四象限拼（足迹 131px） | 保真判据全部停在**图块表字节级**（双 PNG 交叉校验 0 差异），**没有任何一条判据断言"渲染出来的子弹长什么样"** |
| T3 | 间歇无法移动 | 三处静默冻结：暂停零视觉反馈（原版靠音乐提示，M1 裁掉音效后反馈通道消失）、死亡瞬间消失、Enter 快按被整帧丢弃 | 判据全是**机制正确性**（碰撞/出生/伤害），没有一条覆盖"**状态切换必须对用户可见**" |
| T6 | 所有坦克无法左右移动 | ① 敌方 AI 方向选择：ROM `CalcDirToTarget`（$DDA0）是 9 项×2 组方向表（X/Y 轴各 50% 偏好），实现简化成"取差值更大的轴"→ 追基地时纵向恒占优，**敌坦全局永不横向**；② 基地 Π 墙 `(12,5)` 位掩码 `0b1010`（仅右半格砖）被填成整格 → 出生点向右多挡一格 | 方向表**就在 `.research/upstream/REVERSE.md` 里**（阶段 1 取回），但设计转写时丢掉了它，且**没有任何判据引用它**；鹰墙掩码是同类转写错误 |

**关键事实**：T5→T6 之间**零代码改动**（transcript 逐事件核查）——T6 的 bug 不是修复轮引入的新回归，而是**T3 修复轮交付时就带着的存量**。"四方向全部可动"的交付声称只在出生点特定场景下验证过。

## 2. 流程级诊断：三个结构性洞

### 洞 1：判据集 = 作者的盲区集（最重要）

全部四道闸（面板/门下门/对抗审查/探针）验证的都是**作者写出来的判据**。作者没想到"敌坦方向分布"该有判据 → 判据表里没有 → 所有闸门对这条维度结构性失明。对抗审查攻击的是 diff vs 设计，门下门审的是计划 vs 设计——**没有一道闸把"设计+实现"对照外部真值做完整性核查**。外部接地把真值取回来了，但"取回"不等于"转写"，更不等于"被判据引用"。

实盘中这个洞反复出现：子弹银行（真值在 REVERSE.md）、AI 方向表（同）、鹰墙掩码（同）、爆炸颜色（上游参考实现 vs 真机印象，至今存疑）。**复刻类任务的头号缺陷类别是"真值转写错误"，而闸门集对这个类别零覆盖。**

### 洞 2：没有"玩一遍"闸（用户视角缺位）

三轮 bug 全是**用户上手三分钟**发现的。流程里有 240k 帧随机输入 soak——但它是 bug 报告**之后**为验证特定假设（碰撞死锁）临时写的，不变量只有"四向全堵次数"。T3 修复后同样的取证模式（子弹足迹 ≤18px、暂停前后画面必须有差异）也是事后补的。**这些不变量如果在交付前就是判据，三个 bug 一个都出不了门。**

### 洞 3：修复轮的回归闸弱于首轮交付

T3 修复轮自造了一次回归（地形负数索引约定废除未扫类 → 整片砖墙变虚线），**靠看截图目视才发现**。bugfix.md 只要求"全量测试"，不要求重跑变异探针与受影响 E2E；修复轮的对抗审查也缺位。首轮交付的闸门密度远高于修复轮——而修复轮恰恰是改动共享基础设施（取表层、输入层）的高危场景。

## 3. 改进提案（按优先级）

### P0-1 复刻/对接类任务：真值转写清单化（进 full-dev 阶段 1）

外部接地产出的每张真值表（方向表/位掩码/图块表/调色板/数值表）必须落成**逐条目的转写清单**：
每条目三态——已转写（带判据编号）/ 显式豁免（带理由）/ 未转写。门下门与对抗审查各加一条机械问题：
"清单里有没有'未转写且无豁免理由'的条目？"。**清单即判据覆盖率的审计面**——把洞 1 从"作者想不到"变成"清单上有空格"。

### P0-2 交付前 playtest 闸（进 full-dev 阶段 4）

交付前必须跑一轮**用户视角不变量 soak**：随机/脚本输入驱动真实运行，断言一组
"用户可感知"不变量——本轮实证的反面教材直接转成模板：
- 实体的渲染足迹/形状判据（子弹足迹 131px → ≤18px 这类断言交付前就该存在）
- 状态切换画面可见性（暂停/死亡/结束前后帧必须有差异）
- 行为分布不变量（"敌坦 1000 帧内必有横向位移"）
不变量从验收判据推导，写不出来的一律标 `[manual-verify]` 并给用户具体步骤——不得静默缺省。

### P1-1 修复轮回归闸对齐首轮（进 bugfix.md）

S2/S3 修复交付前：全量测试 + **变异探针重跑** + 受影响面 E2E 重跑；
改动触及"被多处复用的取表/解析/输入基础设施"时，强制同类扫描（本次砖墙回归的教训：
废除隐式约定必须全仓扫使用点）。

### P1-2 对抗审查加"对照外部真值"维度（进附录 D）

审查材料加上**真值清单**（P0-1 的产物），审查员须回答："实现与清单里的每个已转写条目一致吗"——
而不只是"实现与设计一致吗"。本轮对抗审查抓了假证据和死模块（设计内缺陷），
但子弹银行这种**设计本身就错**的缺陷结构性地漏掉了。

### P2 流程违规补记

首轮实现期违反"裁决未出前禁止进入实现"（面板审查在跑时主线程已开始写 `src/`），
transcript 有明确时序证据。该条款已有，缺的是违规检测——cost-report 可加一条
"首个 src/ 写入早于门下门 approve"的事后审计指标（事件锚已就位，B5 修复后可直接算）。

## 4. 也要记下的成立部分

- 三轮 bug 的**取证质量**都很高：BFS 可通行性证明"不是碰撞"（240k 帧 0 次四向全堵）、
  逐字节帧比对证明"暂停零反馈"、渲染候选图块定性银行归属、ROM 地址级根因。
  "先取证再修"的纪律在修复轮是守住了的。
- 判据反向确认（变异探针）在修复轮继续抓真问题：两条"仍绿"探针暴露护盾判据太弱、鹰无判据。
- 第二方复核传统延续：T6 的根因由会话自己的取证定位（非用户提示），且复现测试先行。
