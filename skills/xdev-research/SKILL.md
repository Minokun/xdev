# /xdev-research — 算法研究流程

**研究输入：** 用户消息（手势之外的原文）

> 本流程不是独立流程，而是 xdev 体系的研究特化——**复用 full-dev 的整套机制，只替换审查维度**：
> 三审查员面板 + 门下门（A1–A4 → R1a–R1c + R1 门下门）、worker receipt 派发、drift check
> （对照基准换成预注册 proposal.md）、pre-landing 对抗审查（附录 D → 报告对抗审查）。
> 三大机制的映射：**对照基准 = 预注册的假设与判定阈值**（≈ Intent Contract），
> **真实执行 = 实验真跑且指标落盘**，**fresh 审核 = 研究视角的审查员面板 + 结果溯源审计**。
> 硬规则 1–5 全部生效（定义见 `/xdev-full-dev`，速览见本文附录 H），另有研究专属铁律 T1–T3（见下）。
> 设计依据：AI-Scientist / Agent Laboratory / RE-Bench / SWE-bench 的自动实验经验——
> 预注册防事后调标、指标必须由落盘文件解析、评测集固定禁子采样、负结果同样落盘；
> 以及 DeepResearch 类系统（Anthropic multi-agent research、STORM、plan-execute-replan）经验——
> 三视角开局、orchestrator-worker + 文件系统产物指针（防传话失真）、replan 循环显式退出条件。
> 专业实践溯源（均已在线验证，对应机制见正文）：OSF 严格预注册与 Registered Reports
> （预注册门禁 + if-then 决策树 + 结局分级）；晶体学 R-free（留出集调优/终判分离 + 访问记账）；
> cryo-EM 金标准半图（关键数字双路独立复算）；CASP（对应物 = **judge 机器盲判**——不看叙述只看数字，
> fresh 审查员提供独立性而非盲性，如实声明）；wwPDB OneDep（judge 输出作为机器验证产物随报告归档）；
> FLT blueprint / Prove2Me（matrix 先冻结后执行、陈述与执行分离、文件系统充当多智能体共享记忆）；
> NCI 实验记录规范（append-only + SHA-256 哈希链信任锚）。

## 研究专属铁律（在通用 5 条之上，违反即流程失败）

- **T1 预注册不可逆**：假设（H0/H1）、判定阈值、评测集、seed 数一经用户确认
  （阶段 2 门禁单次确认，或授权包内的预授权生效），分析阶段只许判定不许改；
  要改 = 显式回到阶段 2 重新过门禁并留痕。
  **T1 的事实性前提例外（与 `/xdev-full-dev` 阶段 1 的外部接地检查同构）**：预注册里凡出现
  "这个数据拿不到 / 只能手工构造 / 没有现成实现 / 上游不支持"这类**关于外部世界的断言**，
  它**不是**"已批准的决策"，而是**待核实的断言**——必须先验证（取回权威源 / 跑通一次最小复现），
  或显式标注"未验证"并说明它若为假会怎样推翻整个方向。
  理由：预注册是**更强版本的设计公理**，而开发侧的实盘已经证明——一个被写成前提的错误断言
  会让全部下游闸门（12 位审核员 × 6 轮）在结构上被禁止质疑它。研究侧的代价更大：不是返工一次交付，
  而是**烧掉一整轮实验预算后才发现方向建在假前提上**。
  写法：`前提：<断言> | 证据：<命令输出/来源 URL/file:line> | 或：未验证→它会推翻什么`。
- **T2 数字必须溯源**：报告/结论中的每个数字必须指向 `runs/` 下真实存在且通过哈希链校验的
  metrics 文件路径；由模型凭记忆写出的数字一律无效。评测集固定，禁止子采样挑好结果。
  **溯源目标必须在持久位置**（研究目录/仓库入库）；指向 /tmp、会话缓存等易失位置的证据视为无证据。
  **解析脚本自身也要可伪证**（硬规则 2 的研究侧形态）：喂一份**故意改坏**的日志/指标，解析脚本
  必须报错或算出不同的数——恒绿的解析脚本与恒绿的断言等价，而它会污染整条溯源链。
- **T3 负结果同样落盘**：假设被证伪、实验失败、方向走不通，都必须写入报告与实验记录，
  不得只报喜。**用户喊停只阻止开新轮，不豁免已产生数据的报告义务**。

## 阶段 0：范围门控（先判断，再动手）

| 输入实际是 | 去向 |
|---|---|
| 概念问题 / "这个算法靠谱吗" 的只读评估 | `/xdev-ask` |
| 理论推导 / 证明正确性验证（无实验可做） | `/xdev-ask`（需要推导过程的深度分析，本流程的实验阶段无对应物） |
| 复现失败、实验代码报错 | `/xdev-bugfix`（复现本身是研究目标时，修完回本流程） |
| 实验代码小改 / 换超参重跑，**不需要新研究结论** | `/xdev-iterate` |
| 把已验证算法工程化为功能/库 | `/xdev-full-dev` |
| 涉及人类受试者数据 / 生物安全 / 双重用途 | 🔴 显式升级用户——本流程不替代 IRB/伦理审查 |
| 给思路/论文要方案与实验、调参找规律（要结论） | **留在本流程** |
| 说不清 | 默认本流程起手，阶段 1 结束后再分流 |

判定一行话告知用户。同时定 **effort 档位**（触发条件不硬编码，但档位对应的要求在该档内生效；
边界 ±20% 内可由用户选档）：

- **mini**（1–3 run，半天内）：免三视角派发、免方向看板、免面板与门下门；proposal 落盘四行
  （H1 / 判定阈值 / 阈值依据 / 用户确认时间）经用户确认即生效；R2 退化为单点数字核对；
  结论只许标"**初步支持**"，不得上方向看板当定论。
- **标准**（≤10 run）：完整流程。
- **攻坚**（>10 run 或跨天）：完整流程 + state.md 固定头部强制 + 阶段 3 结束才许汇报。

## 阶段 1：文献与现状（先穷尽材料源，再三视角派发）

**第 0 步：材料源清单（自主搜集，不等用户喂）**。开工前先盘点并读取所有可接触的材料：

| 材料源 | 搜集动作 | 优先级 |
|---|---|---|
| 用户给出 | 用户贴的思路/论文/笔记/约束条件，逐条摘入 literature.md §用户输入 | **最高——用户的约束是硬约束，与文献/惯例冲突时以用户为准或显式提问** |
| 项目内 | 仓库代码、docs/、**docs/research/ 下的历史研究目录**（承接过往结论，禁止重复造轮子）、数据目录、已有 runs/ | 高 |
| 网络 | web_search/web_fetch：论文题、方法名、公开榜单/数据集、官方文档 | 中（须标注"在线已验证"） |
| 训练知识 | 模型自带知识 | 兜底（必须标注"未在线验证"） |

材料不足时**先搜集再提问**：能自己找到的不要问用户；只有目标本身歧义（要优化什么指标、约束边界）才回头问。

然后并行派发 fresh subagent（互不知道彼此结论；模拟 STORM 的多视角提问）：

| 派发 | 任务 | 产物 |
|---|---|---|
| A 文献 | 该思路的相关论文/已知方法/公开指标。**网络可用时必须先用 web_search/web_fetch 在线检索**（论文题、方法名、公开榜单），训练知识仅作补充；每条来源标注可信级（在线已验证 / 训练知识未验证） | literature.md §相关工作 |
| B 现状 | 仓库/数据/环境盘点：现有代码能不能跑、数据在哪、基线是否存在；**含 preflight 环境检查**（网络/GPU/依赖/数据可达性逐一真跑验证）——环境级不可行在此 fail-fast，不进入后续阶段烧审查资源 | literature.md §现状 |
| C 对手 | 站在反方：这个思路最可能死在哪（已知失败模式、理论瓶颈） | literature.md §风险 |

网络不可用/资料不足时如实标注"未在线验证"，禁止编造引用（铁律 T2 的引用版）。

**三份材料合并后必须产出方向看板 `directions.md`**（这是阶段 1 的核心交付物，不是可选项）：
从目标出发列出 **≥2 个候选方向**（文献里已验证的路线、现状支持的路线、对手视角认为该避开的路线都要纳入），
每方向一行：假设雏形 / 预期收益 / 成本估计 / 最大风险 / 排序依据，按"期望收益÷成本"排序。
同时给用户 **≤5 行简报**：值得做吗 / 方向看板摘要 / 推荐先试哪个 / 最大的坑。
**方向看板是活文档**：之后每轮实验结束都要回写状态（未试/证实/证伪/搁置）并重排剩余方向——
下一轮选哪个方向，由上一轮结论驱动，不靠拍脑袋。
**看板纪律**：方向的降级/剔除必须写明证据字段（指向具体 run 的 metrics），不许只写推断；
推断性剔除（"X 的失败原因可能也适用于 Y"）单独标注，交 R2 审计核对。

## 阶段 2：假设与实验方案（预注册，🔴 门禁）

**一轮只预注册一个方向**（方向 = 同一假设族）：从 directions.md 取排序最前的未试方向（或用户指定），
为它写 proposal.md；其余方向留在看板上排队。矩阵内多个方法格必须服务同一 H1，
基线格是对照不是新方向，不计违规。

proposal.md 必含（缺一不过门）：

1. **假设**：H0 / H1 各一句，可证伪
2. **预期效应量与判定阈值**：如"H1 成立当且仅当 method-A 在 <评测集> 上比 <基线> 高 ≥x 个点
   **且 bootstrap 95% CI 不含 0**（≥5 seed）"——分析阶段只判定不解释；seed=3 的结论强制标"探索性"
3. **实验矩阵**：方法 × 数据集 × 超参 × seed，每格一个 run；**seed 值列表与 run 执行顺序
   在此随机化并落盘**（ARRIVE 随机化实践——防环境漂移与方法顺序混杂）
4. **评测集与基线**：固定、全量、禁子采样，附**数据集哈希**；基线数字注明来源（自己跑 or 引用）
5. **Must Not**：明确不做的方向（防扩散）
6. **预算**：预计 run 数 / 时长 / 算力；**任一维度达申报值 ×2 即触发用户确认**；
   预算在基线复现成功后须复核一次并留痕
7. **留出集声明**（晶体学 R-free 实践）：评测集划分调优集 / 留出集（holdout），**划分 seed 与
   数据哈希落盘**；调优、迭代、补跑的判定只触调优集；留出集仅在终判使用一次，
   提前使用或重复使用即视为污染，该结论作废重报
8. **if-then 决策树**（OSF 严格预注册）：前提被违反时的备选方案预先声明
   （如指标分布不满足 → 启用哪个备选指标/检验），执行中禁止临时换未声明的方法
9. **效力依据与正交指标**：给出最小可检测效应（MDE）论证（效应量先验 × 方差先验 × seed 数，
   允许粗略但必须有数字）；禁止边跑边加样本直到显著（p-hacking）；
   关键结论须 ≥2 个独立指标维度交叉确认（单一指标可被博弈）
10. **结局分级**（OSF 结局预声明）：声明 **primary 结局 ≤2 个**，其余标"探索性（未校正）"；
    多个 primary 假设同时检验时声明多重比较校正方法（Holm/Bonferroni，或显式写明不校正的理由）
11. **metrics schema 与 judge 判定逻辑**：metrics.json 的字段契约 + judge 的判定伪代码
    （contract-first：schema 与判定逻辑在此冻结；真实日志 → schema 的解析脚本属执行侧，阶段 3 开发）
12. **预注册生效记录**（门禁通过后回填）：用户确认时间戳 + 决策简报 + 面板结论 +
    proposal/matrix 内容哈希——跨会话恢复时以此为准，不重过门禁。
    **哈希纪律（实盘教训）**：先完成全部冻结时回填（生效时间、面板结论等）**再**计算内容哈希，
    记录值必须能直接复验当前文件（sha256sum 一致）；确需哈希后再回填的，双值并录
    （冻结内容哈希 + 回填后文件哈希）并注明差异原因——记录值与文件实测值失配且无说明
    即视为审计断链

**门禁（标准档与攻坚档不可跳过，结构对齐 full-dev 阶段 2：面板 + 门下门）**：
并行派发 **3 个 fresh 审查员**（prompt 见附录 R1a/R1b/R1c；审核员失败重派 1 次，仍失败标 missing，
其维度按"存在 HIGH"处理——同 full-dev 纪律）：

| 审查员 | 研究视角 | HIGH 判定 |
|---|---|---|
| R1a 方法论 | 可证伪性、对照/基线设计、混杂变量、统计功效（对照 MDE 数字审） | H1 无机械判定阈值；MDE 论证缺失或自洽性破裂；缺对照组 |
| R1b 可行性 | 数据/基线/算力/时长是否真实可得（对照阶段 1 现状盘点与 preflight） | 依赖不存在的数据或算力；预算与 run 数明显不匹配 |
| R1c 可验证性 | metrics schema 可否机械解析、matrix 每格可独立复现、if-then 分支在 judge 中有无对应实现 | 指标只能"肉眼看日志"；run 间有隐藏耦合；if-then 分支无 judge 覆盖 |

HIGH 必须修复后重审受影响项；MEDIUM 权衡处理记一句理由。
面板通过后进 **R1 门下门**：fresh subagent 二值裁决（approve/reject，prompt 见附录 R1，
含注入防护与 decision_brief）。reject → 修订 + 逐条修改说明重审，**≤2 轮**（与 `/xdev-full-dev` 及
`full-dev-gate.js` 的 `MAX_ROUNDS` 一致），第 2 轮起先校验
修改说明与实际变更的一致性**（同 full-dev A4 纪律）。
approve 后经 ask_user_question 呈决策简报给用户**单次确认**。**用户确认 = 预注册生效**，
随即回填必含项 12 并把内容哈希写入 state.md。
裁决未出前禁止开跑（等待期间只允许只读准备：读数据/盘点环境）。

## 阶段 3：实验执行（真实跑，状态外置）

- 实验代码走开发流纪律：先写**能复现基线/现象的脚本**并真跑通过，再上方法（对照 SWE-bench 经验：
  先确认现象存在）；**基线复现成功后复核预算估计**并留痕
- **blueprint 纪律（FLT/Prove2Me 教训）**：matrix.yaml **先冻结后执行**——"陈述"（每 run 的
  config/接口定义）与"执行"分离。**冻结语义 = 已有格子不可改；追加新格子是 append-only 留痕操作，
  属补跑迭代，不回阶段 2**；改已有格子才回阶段 2。多 agent 协作时 matrix.yaml + state.md + runs/
  是**唯一共享记忆**（Prove2Me 的教训：无显式共享状态时多智能体协作必然状态丢失、协作崩溃），
  禁止靠对话上下文传递实验状态
- **解析脚本时序**：基线 smoke run → 用真实日志生成 fixture → 解析脚本单测真实通过（硬规则 1）
  → 才许批量跑。metrics.json 只能由验证过的解析脚本生成，**不是模型手写**
- **run 生命周期**：每个 run 独立目录、独立进程。启动时写 `runtime.json`（pid/pgid 或集群 job id、
  启动命令、日志路径）；**预期超会话的 run 必须 detached 启动**（setsid/nohup + pidfile），
  会话结束不杀 run，跨会话靠 pidfile 判活 + 日志断点续判
- **派发纪律（复用 full-dev 阶段 3）**：互不依赖的 run 并行派发 subagent / `run_in_background`；
  **worker 单次尝试原则**——失败即返回，重试计数与诊断归主线程，每次 attempt 落盘 state.md；
  worker 的 receipt（命令/输出摘要/落盘路径）同步落盘 `runs/<id>/receipt.md`，不只是对话产物
- 每个 run 落盘：config 副本（含代码 git commit 与数据集哈希）、append-only 日志
  （**头部强制环境指纹**：时间戳/git commit/数据集 SHA256/硬件标识）、metrics.json。
  **run 结束即对目录算 SHA-256 manifest，追加进 state.md 形成哈希链**——审计与被审计对象不再同源
- **批次 drift check（复用 full-dev 附录 B 精神，对照基准 = 预注册 proposal.md）**：批 = 单次并行
  派发组或累计 ≥5 个 run，先到为准。fresh subagent 对照 diff 与 runs/ 日志，只报"未申报的步骤
  偏差 / 代码变更 / 评测集变动"；已申报的调整不算 drift。未申报偏差 → 该批 run 结论降权并标注
- 单 run 3 次失败（run 级失败，环境级失败由 preflight fail-fast 拦截、不走重试）→
  **换实现路径重试一次**（同假设同格子内调整；换"方向"是轮级动作，必须回阶段 2），
  再败标记 FAILED 落盘并继续其余 run（铁律 T3）
- **留出集批次隔离（实盘教训）**：调优集 run 与留出集 run 分批派发，批间设 tune 筛选检查点——
  预注册声明了"tune 淘汰组不跑 holdout"的，混批启动会让该检查点结构性失效，
  "不看 holdout"从结构保障降级为纯自律
- state.md 固定头部（当前阶段 / 已过门禁及哈希 / 待办 / 活跃 job）**阶段切换即更新**；
  跨会话恢复 = 读 state.md 头部 + runs/ 目录，不重过已通过的门禁
- 分支纪律（硬规则 4 对应物）：研究产物随 feature 分支提交；runs/ 大日志可按项目惯例 gitignore，
  但 metrics.json / manifest / receipt.md / runtime.json 必须入库
- 🔴 任一预算维度超申报 ×2、或需要删数据/占大额算力 → 用户确认

## 值守与心跳纪律（长任务监控——实盘教训：detached 批量启动即死后静默断档 9.5 小时）

- **派发即验证**：远程/detached 任务启动后 60 秒内必须实测一次（pid 存活 + 日志首行 /
  输出开始增长）——"启动即死"是最高发故障；验证失败立即修复重派。
- **心跳登记与实测**：派发时在 state.md 登记 {host, pid/job, 日志路径, 预期产出文件, 预计时长}；
  此后每次唤醒（goal 续轮 / 会话恢复）必须实测三项：pid 存活、日志尾部、产出 mtime 增长。
  **无实测支撑不得在 state.md 写"运行中"**。
- **stall 升级**：连续 2 次心跳无进展 → 查因（pid 死 / 日志报错 / 资源被抢）→ 修复重启；
  无法自修 → 升级用户，不得静默等待。
- **等待期静默**：等 subagent / 后台任务期间，goal 续轮若无新产物只做最小检查、不展开汇报
  （空转轮次是实测发现的 token 浪费源）；subagent settle 通知是主唤醒源，goal 轮仅作兜底。
- **值守能力诚实声明**：goal 自动续轮依赖 harness 进程存活且机器不睡眠。预期超过数小时的
  无人值守任务必须向用户明示此前提，并优先采用服务器侧自续跑（nohup + 看门狗自检脚本），
  会话只负责验收。
- **监控失灵也是失败事件**（T3 延伸）：断档、漏检、心跳未执行本身必须记入 state.md
  （发生时段 / 发现方式 / 影响）——只记实验失败、不记监控失败，会让时间线在审计中显得连续。

## 阶段 4：分析判定（只读落盘指标，机器裁判）

- **判定由 judge 脚本机械执行**（编译器即裁判）：脚本读 `runs/*/metrics.json` + 预注册阈值与
  判定逻辑，输出逐格与矩阵级结论；**fail-closed**——解析失败/格式漂移/缺 run 即中止报错，
  禁止静默剔除（静默剔除会把噪声变成显著）。judge 输出原文落盘 `judge/output-<轮次>.md` 随报告归档
- 判定形态：均值差 ≥ 预注册阈值 **且 bootstrap 95% CI 不含 0**；多 seed 报均值 ± 方差；
  seed=3 一律标"探索性"；异常 run 如实列出
- 结论只有三种：**证实 / 证伪 / 不确定（数据不足以判定）**——"不确定"必须写清缺什么
- **关键数字双路独立复算（标准档及以上默认；cryo-EM 金标准半图实践）**：由两个互不见对方实现的
  fresh subagent 各写一条解析路径，从原始输出分别复算关键指标，一致才采信，不一致先查解析管线
- **补跑迭代（plan-execute-reflect，同一预注册内 ≤2 次）**：结论为"不确定"或"证伪但有明确可修的
  gap"时，允许 gap 分析 → 追加 run（append-only 进 matrix.yaml，不动已有格子与阈值）→ 补跑，
  **判定只用调优集**（留出集留给终判）。**补跑组与原矩阵分组报告，禁止合并聚合**——合并会让
  "3 seed 阈值"实际作用在 6 seed 估计量上，等于没改数字的事后调标。每轮补跑在 proposal.md 追加留痕

## 轮级循环与终止条件（start / end 语义）

**开始条件**：输入可以只有目标或一句话想法（背景、条件、数据现状全部由阶段 1 补齐盘点）。
**阶段 2 预注册门禁通过 = 研究正式开始**；若目标无法落成可证伪假设，门禁 reject 并带具体问题
回来找用户澄清——宁可不开跑，不带病开跑。

**轮级循环（证伪 ≠ 结束）**：一轮（预注册 → 实验 → 判定 → 溯源审计）走完后，
**先把结论回写方向看板**：本轮方向标记 证实/证伪/不确定 + 关键数字 + 该结论对剩余方向排序的影响；
方向的降级/剔除必须带 run 证据字段，推断性剔除单独标注待审。
随后只要看板上还有未试方向，可开新一轮：从看板取下一方向 → **回阶段 2 重新预注册**
（用户确认 + proposal.md 追加留痕；变体方向须声明这是累计第 N 次尝试）→ 阶段 3–5。
轮数不设硬上限，但每开新一轮必须先给用户一行简报：已证伪什么 / **被剔除方向及依据** /
下一轮赌什么 / 累计预算消耗，用户确认后才烧下一笔算力。

**授权包（一次性议定，替代逐轮卡点）**：首轮预注册确认时，与用户一并议定并落盘三项——
① **方向优先序**（看板前几位的推进顺序）；② **预算信封**（累计算力 / 时长 / 人审小时上限）；
③ **自动推进范围**。信封内的轮次切换**自动进行**：阶段 2 门禁面板与门下门照跑、proposal 照写、
报告与审计照出，**预注册于门下门 approve 即生效**（用户确认已在授权包签署时前置完成，
生效记录引用授权包）。只有命中升级触发器才停下来找用户：预算触信封上限、门禁连续 2 轮
不收敛、看板外新方向、需要用户本人资源（如人审标注）、五终止条件之一。
授权包外或无授权包时退回默认：每轮简报 + 确认。用户喊停随时生效（终止条件 5）。

**终止条件（只有五个，全部合法）**：

1. **证实收尾**：H1 按预注册阈值证实 → 阶段 5 报告 → 进入下方"更优选择"；
2. **方向穷尽**：所有可行方向均已证伪 → 强制收尾出负结果报告（铁律 T3）——合法结局，不是流程失败；
3. **预算耗尽**：累计消耗触及预算 ×2 → 收尾并如实报告已得结论与未竟之事；
4. **环境不可行**：preflight 或执行中确认资源/环境不可得且无替代 → 收尾报告已盘点结论；
5. **用户喊停**：随时生效，但**只阻止开新轮——已产生数据的判定与负结果必须先落盘成报告**（铁律 T3）。

**成功后的"更优"选择（H1 证实 ≠ 自动结束）**：给用户三选一——
a) 收尾交付报告；b) 追求更优：立**新假设 H1′（更高标准/更严指标），重新走阶段 2 预注册门禁**——
禁止在旧预注册上渐变提高阈值（那是事后调标）；c) 算法已够用 → `/xdev-full-dev` 工程化交付。
本流程没有自然终点：选 b 持续下去的合法理由是"边际收益仍大于边际成本"，每轮由用户判定。

## 阶段 5：报告（溯源 + 对抗审查 + 机器预检）

report.md（按轮追加；终稿）必含：结论 → 关键数字表（每格带 `runs/<id>/metrics.json` 路径）→
**预注册结局核对表**（每条预注册结局 → 判定 → run 路径，逐条无遗漏，含难看的）→
负结果与失败 run → 复现步骤（命令级）→ 环境元数据（git commit / 依赖 lock / 数据集哈希）→
judge 原始输出归档路径。

**结果溯源审计（fresh subagent，prompt 见附录 R2）**：先跑**机器预检脚本**（引用路径存在性 /
数值对账 / 格子数对账 / 哈希链校验 / 留出集记账对账），LLM 审计员只吃预检报告 + 抽样材料
（每种失败模式 ≥1 + 随机 10% run），并**抽样 ≥2 个 run 从原始日志手工重算**（禁止跑原解析脚本）。
reject → 返工分析或修正报告，不得软化。
**每轮必做，不只终稿做**：单轮结论（哪怕只是看板回写引用的数字）也要过审计后才许驱动下一轮决策。

**对抗审查（fresh subagent，复用 full-dev 附录 D 精神）**：假设这份报告会误导读者，找出最可能的 3 条途径。

**交付签收**：随机复跑 1 个最便宜的 run，结果与原 metrics 一致才许交付（执行真实性的最终锚点）。

### 附录 H：通用硬规则 1–5 速览（全文见 /xdev-full-dev）

1. 验证必须真实执行，禁止"应该会通过"，后台命令轮询到终态；
2. **判据必须可伪证**——先证明它会失败再声明它通过（把实现改坏，判据必须变红；恒绿按未通过处理）。
   研究侧对应物已内建为铁律 T2/T3 的机器裁判与解析脚本测试；
3. fresh 审核的 reject 必须返工或升级用户，不得绕过软化；审核员超时/无回报重派 1 次后标 missing、
   该维度计未知（**不得**因为等不到就当通过）；维度不全的轮次不得 approve；轮次上限 ≤2，
   第 2 轮仍 reject 即升级用户（上限以 `full-dev-gate.js` 的 `MAX_ROUNDS` 为唯一真源）；同类缺陷连续 2 轮命中 → 改设计而非再改文案；
4. 不向 base 分支提交，先建 feature 分支；
5. 不可逆动作须用户确认。

> 阶段划分、文档结构、输出格式均按规模伸缩——但硬规则 1–5 与铁律 T1–T3 不可伸缩。
